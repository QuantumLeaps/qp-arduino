Purpose and Scope

This document (Unique Identifier: DOC-QP-SAS) describes the software architecture for the QP Framework, as it is specified in the QP Software Requirements Specification (DOC-QP-SRS). The scope of this document is to provide a master plan for the overall organization and operation of QP Framework as well as QP Applications to provide the context necessary to understand the framework. The detailed QP Framework design is described in a separate Software Design Specification [DOC-QP-SDS].

Object-Orientation

This Architecture Design Specification assumes an object-oriented point of view, utilizing the concepts of class, inheritance and polymorphism.

Remarks
The object-oriented point of view does not impose the choice of object-oriented programming language. In traditionally procedural languages, such as C, object-oriented concepts can be applied as design patterns. A set of such patterns for the C programming language is described in the reference Object-Oriented Programming in C [OO-in-C:23].

Object-Oriented Framework

This Architecture Design Specification describes an object-oriented software framework, which significantly differs from software organized as a "toolkit", such as a traditional Real-Time Operating System (RTOS).

A software framework (e.g., QP Framework) provides a reusable architecture for a specific problem domain (embedded, real-time systems in case of QP Framework). A framework has key distinguishing characteristics that differentiate it from a "toolkit" (see also Framework vs. Toolkit in DOC-QP-SRS):

  • inversion of control: In a framework, unlike in a toolkit or in standard end-applications, the overall program's flow of control is not dictated by the application, but by the framework.
  • extensibility: application developers can extend the framework by deriving and specializing base classes provided inside the framework.
  • non-modifiable framework code: The framework code, in general, is not supposed to be modified, while accepting application-implemented extensions. In other words, developers can extend the framework, but cannot modify its code.

Note
The mechanism for deriving an application from a software framework, such as QP, is by inheriting the base classes provided by the framework and specializing them for the application at hand. (See also the extensibility characteristics of a framework enumerated above.)
