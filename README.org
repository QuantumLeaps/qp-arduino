* Documentation

This README provides a quick overview of QP for Arduino.

The [[./UPGRADE_QPCPP_V7.md][v7 migration plan]] owns port provenance and
validation status. The [[./docs/observability-plan.md][observability development
plan]] tracks =OBS-QP=: RP2040 QV qualification and a trace pilot within the
shared [[../orb-weaver-context/context/experimental-system-observability-plan.md][experimental-system roadmap]].
As decided 2026-09-30, the Earle Philhower Arduino core family is the primary
RP2040 path; the fixture and exact core/toolchain versions are recorded in the
migration plan, and its software/hardware gates are open. Teensy 4.1 build
regressions remain, but its hardware gates are deferred and do not block RP2040
qualification. STM32G0B1CEU6 is the later second target. None of these plans
establishes new target support or a release.

More detailed documentation for qpcpp, QM, and QTools can be found at:

https://QuantumLeaps.github.io/qp-arduino/

Please refer to the companion website to this project at:

https://www.state-machine.com/arduino

* Description

The Quantum Leaps’ QP™ real-time embedded frameworks (RTEFs) and the QM™
modeling tool complement the Arduino platform and provide everything you need to
program Arduino graphically with event-driven active objects and modern
hierarchical state machines.

* Provided Library and Examples

This repository contains one external library for ARM Cortex-M based Arduinos:

- =qp-arduino= -- QP/C++ framework for Arduinos based on ARM Cortex-M

This repository also contains several examples under =examples/= for:

- Teensy 4.1 (Teensyduino / PlatformIO): =blinky_bsp-teensy4=,
  =dpp_bsp-teensy4=, =port_validation-teensy4=
- RP2040 (Earle Philhower =arduino-pico= core, PlatformIO): =blinky_bsp-rp2040=
  for the recorded qualification fixture
- Arduino Due (ATSAM3X8E): =blinky-sam=, =blinky2-sam=, =blinky_bsp-sam=,
  =dpp_bsp-sam= (best effort, not a support claim)

NOTE: The qpcpp =v7.3.4= source tag used for this package contains generated
framework headers that still report =QP_VERSION_STR "7.3.3"= and
=QP_VERSION 733U=. This package preserves those upstream generated files
unchanged where possible and identifies the imported source by the =v7.3.4=
tag.

The v7 port provenance, file mapping, and intentional Arduino-local deltas are
documented in =UPGRADE_QPCPP_V7.md=. The script
=scripts/check_upstream_provenance.sh= (or =pixi run provenance=) verifies
that imported files still match qpcpp =v7.3.4= except for the documented
Arduino deltas.

The recorded software migration baseline built the Teensy 4.1 examples. RP2040
work uses a recorded non-actuating fixture, a spare =mouse-joystick-pcb= rev 0
board watched by a Kingst LA5032, with the Earle Philhower =arduino-pico= core
pinned in =platformio.ini= (environment =rp2040_mouse_joystick=); see the
fixture record in =UPGRADE_QPCPP_V7.md=. =examples/blinky_bsp-rp2040= is the
first RP2040 example. Further RP2040 examples, BSP/core integration and target
tests remain development work. The imported ARMv6-M QV path is a starting
point, not RP2040 target evidence. QP/QS and application drivers stay on core 0.

=library.properties= still uses =architectures=avr= for the earlier Teensy
packaging decision: Teensyduino installs in Arduino's =avr= namespace. This
unchanged selector neither advertises RP2040 nor proves support for classic
AVR, every Teensy, or any other board. Architecture metadata review is an open
RP2040 gate.

RP2040 and the later STM32G0B1CEU6 target have no SWO/ITM. QS uses an explicitly
qualified UART or other transport; SWD serves programming/debug. The hardware
direction retains passive Digital-50 plus a separate optional debug/trace
connector and a reusable external RP2040 probe. Connector/probe qualification
is independent of the standalone QP fixture and does not allocate DUT pins here.

* Installation

The QP adaptation for Arduino may be used either with the
[[https://www.arduino.cc/en/software][Arduino IDE]] or with
[[https://platformio.org/install/cli][PlatformIO]].

The intended way of working with the examples is to use the
[[https://www.state-machine.com/products/qm/][QM modeling tool]] to modify the
models (=.qm= files) and then to generate code from these models.

In this scenario, the Arduino IDE or PlatformIO are used only to build and
upload the code to the Arduino board(s).

** Arduino IDE

Download and set up the Arduino IDE if necessary:

https://www.arduino.cc/en/software

This library may be installed by either using the Arduino IDE Library Manager or
by downloading this repository into the Sketchbook location directly.

Assuming that you have installed the QP library in your =<Sketchbook>=
directory, the examples provided in each QP library show up in the Arduino IDE
under the menu:

=File|Examples|Examples from Custom Libraries=

NOTE: The preferences in the Arduino IDE should be set up to
=Use external editor= so that the IDE will update the code each time
it is re-generated by the QM modeling tool.

NOTE: QS tracing (=QS_ON=) is enabled by necessity in all Arduino code so the
output is binary. Use QSPY (from QTools) to view the trace stream; a standard
serial terminal/serial monitor is not suitable.

*** Arduino IDE Library Manager

In the Arduino IDE Library Manager, search for qp-arduino and install the latest
version.

*** Downloading into Sketchbook Location

This repository can be downloaded into the Sketchbook location either as a
single zip archive or cloned to a local git repository.

You need to unzip the zip archive, or clone the git repository, into your
Arduino =<Sketchbook>= directory. To find out where your =<Sketchbook>=
directory is, or to configure a different location for your =<Sketchbook>=
directory, you need to open the Arduino IDE and select the =File|Preferences=
menu. The Sketchbook location will be shown at the top of the Preferences dialog
box. Once you identify the =<Sketchbook>= directory, you simply unzip the whole
zip archive, or clone the git repository, to this directory, renaming the
directory qp-arduino if necessary.

After the installation, your Arduino =<Sketchbook>= directory should look as
follows:

#+BEGIN_SRC sh
<Sketchbook>/
└── libraries
    └── qp-arduino
        ├── examples
        │   ├── blinky-sam
        │   ├── blinky2-sam
        │   ├── blinky_bsp-rp2040
        │   ├── blinky_bsp-sam
        │   ├── blinky_bsp-teensy4
        │   ├── dpp_bsp-sam
        │   ├── dpp_bsp-teensy4
        │   └── port_validation-teensy4
        └── src
            └── qp-arduino
#+END_SRC

** PlatformIO (recommended) via Pixi

This repository provides a cross-platform, reproducible command-line workflow
via [[https://pixi.sh/][pixi]] on Linux, macOS and Windows:

- pixi manages the PlatformIO CLI (no manual =venv= / =pip install platformio=)
- pixi tasks select which example to build by setting =PLATFORMIO_SRC_DIR=
  (so you do not edit =platformio.ini=) and give each example its own build
  directory under =.pio/build-examples=
- PlatformIO keeps its platforms and toolchains inside the repository in
  =.pio-core= (set =PLATFORMIO_CORE_DIR= to share one elsewhere)

*** Install pixi

Follow the official installation instructions:

https://pixi.sh/latest/

*** Install dependencies

From the repository root:

#+BEGIN_SRC sh
pixi install
#+END_SRC

*** Build and upload examples

List connected ports/devices:

#+BEGIN_SRC sh
pixi run ports
#+END_SRC

Build and upload the default example (=examples/dpp_bsp-teensy4= on Teensy 4.1):

#+BEGIN_SRC sh
pixi run build
pixi run upload                  # defaults to /dev/ttyACM0
pixi run upload --port /dev/ttyACM1
#+END_SRC

Build or upload any example by naming it and the PlatformIO environment
(=teensy41=, =rp2040_mouse_joystick= or =due=):

#+BEGIN_SRC sh
pixi run build  --example examples/blinky_bsp-rp2040 --env rp2040_mouse_joystick
pixi run upload --example examples/blinky_bsp-rp2040 --env rp2040_mouse_joystick --port /dev/ttyACM0
pixi run monitor --port /dev/ttyACM0
#+END_SRC

Or use the per-example tasks:

#+BEGIN_SRC sh
# Teensy 4.1
pixi run build-blinky-bsp-teensy4
pixi run upload-blinky-bsp-teensy4 /dev/ttyACM0
pixi run build-dpp-bsp-teensy4
pixi run build-port-validation-teensy4

# RP2040 qualification fixture (mouse-joystick-pcb rev 0)
pixi run build-blinky-bsp-rp2040
pixi run upload-blinky-bsp-rp2040 /dev/ttyACM0

# Arduino Due / ATSAM3X8E (best effort)
pixi run build-blinky-sam
pixi run build-blinky2-sam
pixi run build-blinky-bsp-sam
pixi run build-dpp-bsp-sam
#+END_SRC

Regression sets and checks:

#+BEGIN_SRC sh
pixi run provenance      # compare the imported framework files with qpcpp v7.3.4
pixi run build-teensy    # the three Teensy 4.1 examples
pixi run build-rp2040    # the RP2040 examples
pixi run check           # provenance plus the Teensy and RP2040 sets
pixi task list           # everything else
#+END_SRC

NOTE: On macOS the port is typically like =/dev/cu.usbmodemXXXX=, and on Windows
it is typically like =COM3=. The upload tasks accept any port string.

** PlatformIO without Pixi

Every task above is a thin wrapper around =pio= or a Python script in
=tools/=, so any PlatformIO installation works, for example the one described
at https://platformio.org/install/cli or a plain Python virtual environment
with =pip install platformio=. With =pio= on your =PATH=:

#+BEGIN_SRC sh
python tools/pio_task.py build  --example examples/blinky_bsp-teensy4 --env teensy41
python tools/pio_task.py upload --example examples/blinky_bsp-rp2040 --env rp2040_mouse_joystick --port /dev/ttyACM0
python tools/pio_task.py monitor --port /dev/ttyACM0
#+END_SRC

Plain =pio run -e teensy41= also works if you set =PLATFORMIO_SRC_DIR= to the
example directory yourself; =platformio.ini= deliberately sets no =src_dir=.

To use this library from your own PlatformIO project, add the repository URL to
your =platformio.ini=:

#+BEGIN_SRC sh
lib_deps =
    https://github.com/QuantumLeaps/qp-arduino.git
#+END_SRC

** QM and QTools (QM 6.1.1 / QTools 7.3.4)

Only very specific versions of QM and QTools are compatible with the qpcpp
version used by qp-arduino:

- QM: =6.1.1= (binaries are published for Linux and Windows only)
- QTools: =7.3.4= (includes QSPY and QUTest). This version has no binary
  release, so it is cloned from its git tag and =qspy= is built from source
  with =make= and a C compiler, which the pixi environment provides. The
  =qspy= built from that tag reports version 7.3.3, as generated upstream.

This repository provides pixi tasks that download/build these pinned versions
locally into =./.tools/quantum-leaps/= (override with =QL_TOOLS_DIR=).

Install both QM and QTools:

#+BEGIN_SRC sh
pixi run ql-install
#+END_SRC

Launch QM:

#+BEGIN_SRC sh
pixi run qm
#+END_SRC

Install/build QTools only:

#+BEGIN_SRC sh
pixi run qtools-install
#+END_SRC

Run QSPY (arguments are passed through to =qspy=):

#+BEGIN_SRC sh
pixi run qspy -c /dev/ttyACM0 -b 115200
#+END_SRC

If you want QSPY's own help, use the explicit separator:

#+BEGIN_SRC sh
pixi run qspy -- -h
#+END_SRC

* QP/Spy Software Tracing Support

The qpcpp_arm-cm library supports the
[[https://www.state-machine.com/software-tracing][QP/Spy software tracing]].
This feature is also demonstrated in the qpcpp examples (with the BSP).

The Arduino port is always compiled with QP/Spy instrumentation (=Q_SPY=)
because an Arduino build cannot switch it per sketch, so every BSP must
provide the QS callbacks. In this repository QS tracing (=QS_ON=) is therefore
enabled in the BSP-based examples: the Teensy and SAM BSPs define it at the top
of =bsp.cpp=, and the RP2040 environment passes =-DQS_ON= in =platformio.ini=.

NOTE: Because the QP/Spy output is binary, you cannot watch it with a standard
serial terminal. Instead, you need to use the
[[https://www.state-machine.com/qtools/qspy.html][QSPY host utility]].

** QView Demonstration

Once QP/Spy tracing is enabled, the communication with the target system can be
used for [[https://www.state-machine.com/qtools/qview.html][QView visualization and monitoring]].

The =dpp_bsp-teensy4= example demonstrates *QView monitoring*. To see this
feature, upload the =dpp_bsp-teensy4= code to the Teensy 4.1 board and then
launch QView.
